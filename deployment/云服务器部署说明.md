## 当前服务器：Windows Server + 宝塔

当前公网 IP 为 `103.236.57.91`，Node.js `v24.18.0` 已安装在 `C:/BtSoft/nodejs/v24.18.0`。游戏项目目录为 `C:/Games/covenant-server`，使用 **TCP 3001**。服务器上的 **3000 已由其他项目使用**，不要停止其他项目或把本游戏改回 3000。

### 优先通过宝塔界面部署

1. 在宝塔“文件”或服务器资源管理器中，把最新的 `卫戍协议-云服务器部署包.zip` 解压到 `C:/Games/`。压缩包的顶层目录为 `covenant-server`，解压后应能直接找到 `C:/Games/covenant-server/package.json`，避免多嵌套一层同名文件夹。
2. 确认 `package.json` 同级包含 `server`、`shared`、`data`、`public`，并能找到 `server/index.js`。更新已有项目时，先停止本游戏项目，保留其他网站运行，再更新游戏文件。
3. 安装该项目的生产依赖。如果宝塔提供项目依赖安装入口，选择此项目目录和 npm；安装失败或没有入口时，使用下面的手动命令参考。仅在“Node.js 版本管理器”安装 Node，并不等于已安装游戏的 npm 依赖。本次另提供 `卫戍协议-3001修复包.zip`，包含已验证的生产依赖和端口修复文件：把压缩包内容直接解压到现有 `C:/Games/covenant-server/` 并替换对应游戏文件，即可补齐依赖；此修复包依赖现有完整游戏素材，不能单独作为首次部署包。
4. 打开“网站 → Node 项目 → 添加 Node 项目”，按下表填写。目录请通过文件夹选择器选择；若启动选项为空，重新选择包含 `package.json` 的项目目录。

| 配置项 | 填写值 |
| --- | --- |
| 项目名称 | covenant-game（或卫戍协议：盟约） |
| 项目目录 | C:/Games/covenant-server |
| 启动选项 | start:node server/index.js |
| Node 版本 | v24.18.0 |
| 包管理器 | npm |
| 如单独要求端口 | 3001 |
| 域名 | 直接使用公网 IP 时可留空 |

5. 展开“高级设置”，选择指定环境变量，逐行填写：

```text
HOST=0.0.0.0
PORT=3001
NODE_ENV=production
```

6. 点击“确定”，查看项目状态和日志。如果添加项目没有自动启动，在项目列表启动本游戏。若面板提供开机启动选项，启用它。后续由宝塔项目管理持续运行，不要再从终端重复启动同一项目。本次普通 Node 项目日志显示服务安装和启动成功；PM2 是可选托管方式，不应再启动第二份相同服务。服务器重启后的自动恢复尚未做实机验收。
7. 在服务器浏览器打开 [本机健康检查](http://127.0.0.1:3001/healthz)。应收到 JSON，包含 `"ok":true`；`app` 字段应与本次部署的 `package.json` 版本一致。再打开 [本机游戏](http://127.0.0.1:3001/)，确认游戏界面加载和服务器连接正常。
8. 本机验证成功后，确认云厂商端口规则和 Windows 防火墙均允许入站 **TCP 3001**。此前开放的 3000 不能代替 3001；两层规则分别生效。不要关闭整个防火墙。
9. 在玩家电脑打开 [公网健康检查](http://103.236.57.91:3001/healthz) 和 [公网游戏](http://103.236.57.91:3001/)。两名玩家连接同一个公网地址，再通过邀请链接加入同一房间，验证联机。

面板有时显示“Node 项目”或“PM2 项目”；以当前 Windows 面板的入口为准。启动脚本是 `start`，入口是 `server/index.js`。部署包也附带 `ecosystem.config.cjs`，用于支持 PM2 配置文件的管理方式；使用普通 Node 项目设置时无需另行启动它。

### 手动命令参考

以下命令由管理员在服务器 PowerShell 中手动运行。界面流程可用时优先使用界面；临时验证前应先停止宝塔中的本游戏项目。使用已安装 Node 的绝对路径，可避免终端没有刷新 PATH 时出现“无法识别 node”。

安装生产依赖：

```powershell
Set-Location -LiteralPath 'C:\Games\covenant-server'
$gameNodeDir = 'C:\BtSoft\nodejs\v24.18.0'
$env:PATH = "$gameNodeDir;$env:PATH"
& "$gameNodeDir\node.exe" --version
& "$gameNodeDir\npm.cmd" ci --omit=dev --no-audit --no-fund
```

临时前台启动：

```powershell
Set-Location -LiteralPath 'C:\Games\covenant-server'
$env:HOST = '0.0.0.0'
$env:PORT = '3001'
$env:NODE_ENV = 'production'
& 'C:\BtSoft\nodejs\v24.18.0\node.exe' 'server/index.js'
```

这不是长期托管方式，关闭终端可能结束进程。验证结束后停止临时进程，再由宝塔启动。健康检查可直接在浏览器打开，无需向宝塔网页终端粘贴命令。

### 排查连接

- 本机 `/healthz` 无法访问：查看游戏项目状态、依赖安装结果和日志。出现 `ERR_MODULE_NOT_FOUND` 时检查生产依赖；出现 `EADDRINUSE` 时检查是否重复启动了本游戏或 3001 被其他程序占用。
- 本机健康检查成功，公网失败：核对公网 IP、云厂商 TCP 3001 规则和 Windows 防火墙入站规则，并确认环境变量为 `HOST=0.0.0.0`。
- 页面可打开但游戏未连接：检查项目日志和 WebSocket `/ws`。使用 Nginx 等反向代理时，需要转发 WebSocket Upgrade；直接访问本项目的 3001 端口无需额外代理。
- 旧笔记或旧配置仍写着 3000：更新为 3001 后再使用；不要依照旧说明修改正在使用 3000 的其他网站。

## 玩家 EXE 的服务器配置

新版 EXE 从 **EXE 同级目录**读取 `服务器配置.json`。连接此云服务器时填写：

```json
{
  "serverUrl": "http://103.236.57.91:3001/",
  "localPort": 3001
}
```

保存后重新打开 EXE。`serverUrl` 有值时直接连接该 HTTP/HTTPS 游戏地址，关闭玩家 EXE 不会关闭云服务。所有玩家应使用相同地址；房间码只属于该服务器。

本地运行时把 `serverUrl` 改为空字符串：

```json
{
  "serverUrl": "",
  "localPort": 3001
}
```

此时 EXE 默认在本机启动或连接 `127.0.0.1:3001` 的游戏服务；`localPort` 可改为其他未占用端口。远程模式下端口由 `serverUrl` 中的地址决定，`localPort` 不改变云服务器端口。配置文件必须是有效 JSON。

云联机配置需要新版 EXE 支持；未包含此功能的旧 EXE 不会自动连接云服务器。复制玩家成品时保留整个 EXE 成品文件夹，包括资源文件和 `服务器配置.json`。

## 数据和更新

当前游戏从 `data/*.json` 读取静态数据，房间和对局保存在进程内存中。重启或更新服务会结束当前房间与对局，没有独立账号数据库需要导入。云服务器上传部署包，玩家电脑使用 EXE 成品，两者用途不同。

### 更新和回退

1. 在开发机确认本地测试通过，准备完整部署包，并记录 `package.json` 的版本。现有 3001 修复包只覆盖固定运行文件和依赖，不能代替后续功能版本的完整更新。
2. 在宝塔停止本游戏，备份 `C:/Games/covenant-server` 及面板中的启动选项、Node 版本和环境变量。
3. 解压新的完整包；新目录应包含 `server/index.js`、`shared`、`data`、`public`、`package.json` 和锁文件。依赖发生变化时，在项目目录重新安装生产依赖。
4. 由原宝塔项目启动，先检查服务器本机 `/healthz`，再从玩家电脑检查公网接口和游戏页面。`app` 应与目标发布版本一致。
5. 在开发机项目根目录运行下方联机验收脚本，确认开局、同步和重连正常后，再分发对应 EXE 目录。

更新失败时，停止本游戏，恢复备份目录与原启动配置，再检查本机和公网接口。回退文件不会恢复已经结束的内存对局。

```powershell
node scripts/verify-public-network.mjs http://103.236.57.91:3001/
```

此脚本位于开发机完整项目中，服务端部署包不包含 `scripts/`。它会创建真实测试会话和独立房间，完成验证后退出；结果写入开发机的 `deployment/公网联机验证结果.json`。测试结束时可能暂留断线会话用于重连窗口，`sessions` 不必立即归零；重点检查测试房间、对局和连接已退出。

### 运行与维护边界

- 使用单实例运行。本项目的会话、房间和对局保存在单进程内存中，多个独立进程之间没有共享状态；现有 PM2 配置为 `instances: 1`、`fork`。
- 游戏数据在服务启动时载入并缓存，修改 `data/*.json` 后重启服务；同时更新关联素材与资源清单，避免前后端版本不一致。
- `/healthz` 是部署探测接口。`ok=true` 表示接口正常返回，仍需结合 `app`、日志、资源加载和实际联机验证判断版本是否可用。
- 域名或 HTTPS 迁移需要配置反向代理和 WebSocket Upgrade，并将所有玩家的 `serverUrl` 更新为新的游戏地址；仅修改 EXE 的 `localPort` 不会改变云端连接。

开发结构和消息规范分别见[开发文档](../docs/开发文档.md)与[联机协议](../docs/联机协议.md)。

## Ubuntu + 宝塔（其他服务器参考）

当前服务器是 Windows，以上 Windows 路径和 PowerShell 命令适用于当前部署。若以后迁移至 Ubuntu，可将项目解压到 `/www/wwwroot/covenant-server`，安装 Node.js 24.x，并使用同样的启动脚本和环境变量。Linux 的手动依赖安装参考：

```bash
cd /www/wwwroot/covenant-server
npm ci --omit=dev --no-audit --no-fund
```

只在面板项目已停止时临时验证：

```bash
cd /www/wwwroot/covenant-server
HOST=0.0.0.0 PORT=3001 NODE_ENV=production node server/index.js
```

长期运行仍由宝塔 Node/PM2 管理，服务器防火墙和云厂商规则均需允许 TCP 3001。
